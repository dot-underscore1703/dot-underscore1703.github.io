No Versioning (NoVer) Specification Version 0.0.0

Versioning thats pure in form, and practice.

NoVer is a versioning specification that acknowledges that standard versioning is unnecessary. Because at the core of all computing, software is simply just software. Nothing should need 100 thousand different "versions" of the same product. NoVer allows developers and users to be confident in themselves, and the software they use. Using an older version of any software is just plain silly. If you think you need to use an older version of a program, you are a fool. Your brain is flawed, as it cannot comprehend that only the latest version of software is necessary. With security patches, bug fixes and new features, the most recent release is the only thing you need.

Summary

Versioning follows a ZERO.ZERO.ZERO format, where each number is always zero. You may not append any additonal data to the version, as that is what NoVer considers "bloatware". Bloatware in this context is defined as any data that is not necessary for the software to function.

The Details

The key words “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “MAY”, and “OPTIONAL” in this document are to be interpreted as described in RFC 2119.

1. Software using NoVer MUST declare a public API. The API MAY be a library, command line interface, or any other form of API. The API SHOULD be documented in a public, widely accessible location, such as a website or a public repository.

2. A version using NoVer MUST be comprised of three integer values, seperated by periods. Each integer value MUST be zero. With new releases of the software, any component of the version number MUST NOT increment or decrement, and MUST remain exactly zero.

3. Any new release of software using NoVer SHOULD be made absolutely clear to any location the software may be distributed, that it is the most recent release. Earlier releases of the software SHOULD be removed from anywhere it has been distributed, as to avoid confusion. Older builds of the software SHOULD NOT be packaged or disitrbuted alongside the most recent release.

4. Any software using NoVer MUST NOT be distributed on any platform that is unfamiliar with NoVer, as to avoid version conflictions. A distribution service targetting NoVer software MUST NOT include more than one version of the software. The distrbution service SHOULD be sure that it is distributing the most recent release of the software.

5. Any software using NoVer MUST NOT be distributed alongside any software that does not use NoVer.

Examples

Updating software from development phase to release phase
MySoftware 0.0.0 -> MySoftware 0.0.0

Adding a bug fix to the software
MySoftware 0.0.0 -> MySoftware 0.0.0

Making an major, backwards incompatible change to the software
MySoftware 0.0.0 -> MySoftware 0.0.0
